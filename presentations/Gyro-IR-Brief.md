## 2. 안내된 평가 관점

창업형 서비스 발표는 아래 내용을 투자 피칭 형식으로 설명한다.

| 평가 관점 | 발표에서 답할 질문 |
| --- | --- |
| 고객 | 누가 이용하고, 누가 공급하며, 누가 비용을 지불하는가? |
| 제공 가치 | 고객의 어떤 문제를 어떻게 해결하는가? |
| 시장성 | 첫 시장에 어떻게 진입하고, 더 큰 시장으로 확장하려면 무엇을 입증해야 하는가? |
| 수익 모델 | 누구에게 어떤 가치를 판매하고, 반복 구매와 원가가 성립하는가? |
| 기술 구현 | 실제 제품이 작동하는가? 핵심 설계 판단은 무엇인가? |
| AI 활용 | AI가 사용자 경험에서 어떤 역할을 하는가? AI로 개발했다는 설명과 구분되는가? |

**정식 배점표·평가 항목별 가중치·세부 심사 기준은 전달되지 않았다.**
위 표는 안내 내용을 질문으로 풀어 쓴 것이지 공식 채점표가 아니다.

## 3. 사용자가 결정한 발표 목표

- 실제 청중은 대구 IT 기업 대표인 심사위원이다.
- 준비 수준과 태도는 YC 또는 a16z 앞에서 5분 투자 피칭을 한다고 가정한다.
- 단순한 학생 프로젝트 소개보다, 발표 후 실제 투자 논의를 하고 싶게 만드는 사업 설명을 목표로 한다.
- PSST 또는 짧은 투자 피칭에 적합한 구조로 처음부터 재구성한다.
- 시연 영상이 필요하다. 챗봇의 다중 턴 경험이 실제 화면에서 명확하게 보여야 한다.
- YC·a16z가 실제 심사·투자·협력한다는 뜻이 아니며 로고나 지지 표현을 사용하지 않는다.
- 투자 욕구를 유도한다는 목표가 성과·수치·계약을 꾸며도 된다는 허락은 아니다.

## 4. 제품과 사업의 사실 경계

### 현재 제품

Gyro는 **바이브벤처 제작 서비스를 사용자의 문제·관심사에서 출발해 발견하고,
관심을 표현한 뒤 공식 서비스로 연결하는 대화형 서비스 발견 플랫폼**이다.

- 발견자는 가입하지 않는다.
- 기본 발견: 사용자 유형·관심사 선택 → 추천 이유가 있는 카드 → 최대 10장 라운드 → 결과·공식 링크.
- 대화형 발견: 직접 입력한 문제, 선택적 기술 스택·도구, 선택적 공개 GitHub 정보로 후보를 추천한다.
- Copilot SDK는 서버에서 호출하고 추천 ID를 카탈로그 후보 범위와 대조한다.
- 접속 가능성 확인과 공식 링크 중복 제거를 제공한다.
- 관심 있음·없음 및 선택적 의견은 초기 관심 신호다.
- 대화는 Gyro 서버의 영속 저장소·퍼널에 저장하지 않는 구조다.
  외부 AI 제공자 처리 조건까지 “어디에도 저장하지 않는다”고 단정하지 않는다.
- 빌더·공개 댓글은 구현 여부와 별개로 기관·법률·인프라·운영 조건 확인 후 공개한다.
- 기존 외부 skill/MCP 항목의 노출 정책 미정합이 남아 있다. 모든 진입점의 정책 정합성이나
  작품 공개 권한 확인 완료를 주장하지 않는다.

상세 요구사항은 `../prd.md`, 구현 계약은 `../trd.md`가 우선한다.
미승격 사업 비전을 이유로 신규 기능이나 카탈로그 범위를 변경하지 않는다.

### 현재 확보하지 못한 증거

사용자는 2026-11-07 “실제 고객 증거 없음”이라고 답했다.

- 실제 고객 반응·고객 수요 검증 근거 없음.
- 유료 고객·계약·매출·지불 의향에 대한 확인된 근거 없음.
- 공식 기관 도입·협약·승인된 유입 채널 확보 근거 없음.
- 확인된 성장률·유지율·CAC·LTV·마진·시장 규모 수치 없음.
- 창업자 이력·수상·개발 기간·팀 구성에 대한 발표용 확인 정보 없음.
- 투자 요청 금액·기업가치·지분·런웨이는 미정.

제품 구현은 실행 기반이지 트랙션이 아니다. 작품 수는 고객 수가 아니다.
행사 참가 학생 23명도 Gyro 이용자 수가 아니다.

### 비전과 수익 가설

- 바이브벤처는 현재 제품 범위이자 첫 진입점이다.
- 인접 교육·창업 프로그램과 더 넓은 서비스 발견으로의 확장은 미검증 비전이다.
- 초기 수익 가설은 기관 대상 프로그램 단위 운영료다.
  작품 검수·등록, 발견 채널 운영, 관심 반응 집계·정리를 묶어 제안한다.
- 일반 발견자와 참가 학생에게 직접 과금하지 않는 방향이다.
- 요금·구매 이유·반복 구매·검수 및 지원 원가를 고객에게 검증해야 한다.
- 기관 운영료 모델이 곧 범용 플랫폼의 큰 매출로 연결되는 것은 아니다.
  기관 맞춤 운영 대행에 머물 위험과 장기 이용자 재방문 문제를 해결해야 한다.
- 광고·유료 노출·제작자 구독 등 여러 수익원을 이미 구현된 사업처럼 나열하지 않는다.
- 클릭은 외부 서비스 사용 완료가 아니며 관심은 구매·PMF·시장성 확정 판정이 아니다.

### 교육 PoC

약 4주, 작품 10–20개, 자발적 참여자 50–100명 내외는 **협의용 제안 규모**다.
확정된 모집·실적·투자금 예산이 아니다.

작품 게시 권한, 미성년자 보호, 개인정보·문의·삭제 책임, 기관 안내 채널 승인이 선행되어야 한다.
AI 제공자 이용 조건 확인 전 기본 PoC는 AI 없이 가능한 발견 흐름으로 안내한다.
학생 평가나 작품 서열화에 관심 반응을 사용하지 않는다.

## 5. 새 5분 본편 구성

PSST의 Problem·Solution·Scale-up·Team을 내용 점검에 사용하되, 무대에서는 아래 7장 흐름으로
전달한다. 특정 투자기관의 공식 양식이라는 주장은 하지 않는다.

| 시간 | 장 | 핵심 주장 |
| --- | --- | --- |
| 0:00–0:20 | 회사 | 필요한 서비스를 이름을 몰라도 찾게 한다. |
| 0:20–1:05 | 문제·Why now | 서비스가 만들어졌다고 사용자가 생기는 것은 아니다. |
| 1:05–1:50 | 제품·시연 | 사용자의 입력을 카탈로그 후보·추천 이유·선택·공식 연결로 이어준다. |
| 1:50–2:35 | 구현 증거 | 고객 반응은 없지만 시장 검증에 사용할 작동하는 제품을 구축했다. |
| 2:35–3:30 | 첫 시장·확장 | 바이브벤처에서 시작하고 확장 조건을 단계별로 증명한다. |
| 3:30–4:20 | 수익 모델 | 초기 기관 운영료의 구매 이유·반복 구매·원가를 확인한다. |
| 4:20–5:00 | 실행·요청 | 실제 사용 가치와 유료 운영 의사를 확인할 투자 파트너를 찾는다. |

질의응답 부록: 경쟁·차별화, 데이터 해석·공개 운영 조건, 투자 금액·검증 이정표.

**현재 구성의 미완성 부분:** Team은 제품 실행 설명만으로 충분하지 않다. 창업자가 이 문제를 왜
이해하는지에 대한 실제 경험과 실행 사실을 보완해야 한다. 구체적 투자 요청은 비용·기간·목표 산정
후 작성한다. 시장 확장 논리 또한 현재 고객 근거로 입증되지 않았다.

## 6. 디자인 전달 지침

- 현재 v2는 내용 구조 초안이며 최종 시각 디자인이 아니다.
- 사업 논리의 약점을 먼저 검토하고, 한 슬라이드에 하나의 주장만 표현한다.
- 큰 타이포그래피, 충분한 대비, 실제 제품 화면을 우선한다.
- 반복적인 3열 카드·작은 본문·장식용 아이콘·읽어야만 이해되는 복잡한 다이어그램은 피한다.
- 웜 페이퍼·짙은 잉크·절제된 강조색으로 제품과 시각적 연결을 유지한다.
- 본편은 말의 흐름에 집중하고 상세 근거·한계·운영 정책은 부록과 발표 노트에 둔다.
- 본편에서도 계획·비전을 실적으로 오해하게 만드는 제목을 사용하지 않는다.
- 시장 규모·성장률·고객 발언·매출·계약·투자 금액을 생성하지 않는다.
- 제품 도식을 실제 화면처럼 표현하지 않는다. 실제 화면은 실제 캡처를 사용한다.
- 제출용 PDF, 편집 가능한 PPTX, 5분 발표 노트, 질의응답 부록을 만든다.
- 첨부 자료를 외부 도구에 전달할 때 소스·secret·개인정보·허가 없는 학생 자료를 포함하지 않는다.

참고: [YC — How to Design a Better Pitch Deck](https://www.ycombinator.com/blog/how-to-design-a-better-pitch-deck).
핵심 아이디어 5–7개, 읽기 쉬움·단순함·즉시 이해됨을 강조한다.
해당 가이드는 이 덱의 투자 가능성이나 YC·a16z의 승인을 보장하지 않는다.

## 7. 시연 영상과 UI 상태

### 반영한 UI 변경

- 첫 입력의 특정 회의록 예시를 제거하고 일반적인 문제 설명 안내로 변경.
- 대화 후에는 후속 질문·추가 조건용 placeholder와 “메시지 보내기” 버튼으로 전환.
- “나”와 “Gyro” 발화자를 표시하고 응답 준비 상태를 대화 로그 안에 표시.
- 동의·개인정보 안내 및 선택 정보를 전송 후 접되 값은 유지하며 다시 열어 확인·변경 가능.
- Enter 전송, Shift+Enter 줄바꿈, 한글 조합 중 전송 방지.
- 중복 전송·대기 중 새 대화 차단, 실패 시 턴 제거와 입력 복원, 새 초안 덮어쓰기 방지.
- 새 대화는 입력·선택 정보·동의를 초기화.

### 녹화 준비 상태

2026-11-07 확인 시 기존 로컬 API의 `POST /api/assistant/chat`은 404를 반환했다.
카탈로그·헬스 API가 동작한다고 대화 API도 준비됐다고 볼 수 없다.
화면의 다중 턴 동작은 브라우저에 “UI 검증용 모의 응답 · 실제 AI 시연이 아닙니다” 표시를 붙여
모의 응답으로 확인했다. 이는 실제 AI 성공 시연이나 발표용 녹화가 아니다.
모의 설정은 페이지 새로고침으로 제거했고 임시 미리보기 서버는 종료했다.

**실제 AI 시연 영상은 아직 제작하지 않았다.**
녹화 전 현재 소스의 대화 API, Copilot 설정·인증·모델 접근, 요청·응답과 추천 후보를 실제로 확인해야 한다.
비밀번호·API 키·학생 개인정보·비공개 저장소를 화면에 노출하지 않는다.
